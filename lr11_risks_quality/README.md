## 4. Технічний борг

| Поле | Значення |
| --- | --- |
| Записів у `techdebt.csv` | 3 |
| Разом годин на повернення | 24 |
| Стеля годин V02 | 900 |
| Борг у відсотках від стелі | 2.67% |
| Рішення pay_now / pay_later / accept | 1 / 1 / 1 |

Борг виник через прийняття вимог безпеки у фіксовану дату: очищення старих
тестових облікових записів, великий тест експорту та винесене джерело політики
не стали блокерами REL-1. Це свідомі, записані рішення, а не прихована
незавершеність.

Я свідомо не гашу D-03: окреме автоматичне джерело політики коштує більше, ніж
дає цінності до появи затвердженого власника політики.

Замовнику це означає, що сьогодні реліз можна прийняти вчасно, але зміна
політики або великий запит на журнал пізніше потребуватимуть додатково 16
годин роботи, щоб не робити це вручну.
