## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний Python-скрипт |
| Прогонів | 10 000 |
| Що тягнеться випадково | фактична velocity одного спринта з масиву [10, 10] |
| Дата, від якої відлічуються спринти прогнозу | для сценарію «весь перший реліз» — початок спринта 1 (2026-10-09), для сценарію залишку — кінець спринта 2 (2026-11-06) |

```python
import math
import random

random.seed(42)
velocity = [10, 10]


def run_forecast(target_points):
    sims = []
    for _ in range(10000):
        total = 0
        sprints = 0
        while total < target_points:
            total += random.choice(velocity)
            sprints += 1
        sims.append(sprints)
    sims.sort()
    p50 = sims[math.ceil(0.50 * len(sims)) - 1]
    p85 = sims[math.ceil(0.85 * len(sims)) - 1]
    return p50, p85


# REL-1 = 45 SP
p50, p85 = run_forecast(45)
print(p50, p85)

# залишок після моїх двох спринтів = 25 SP
print(run_forecast(25))
```

У формулі дати я використав правило FC-3: різниця між `p85_date` і `p50_date` завжди дорівнює `(p85_sprints - p50_sprints) * 14 днів`.

Вузький інтервал не означає “точність”, а лише “низьку варіативність в цій конкретній вибірці”; тому P85 все ще важливий як межа ризику, а не як гарантія надійності.

## 6. Що я кажу замовнику

Дата вголос: 2026-12-18 за плановою velocity 10 SP/спринт. Після двох
спринтів залишаються 25 SP, тому Спринти 3–5 не можна вважати завершеними.
