## 1. Definition of Workflow

| Колонка | Картка потрапляє сюди, коли | Картка виходить звідси, коли |
| --- | --- | --- |
| Backlog | Роботу заплановано, але не взято в найближчий тиждень. | Робота декомпозована, зрозуміла і береться в найближчий план. |
| Ready | Зрозуміло, що є критерієм завершення, і завдання розбите до розміру 1-2 днів роботи. | Я фізично починаю над нею працювати. |
| In progress | Я фактично починаю писати текст, код або створювати документ за карткою. | Роботу виконано, але вона потребує фінальної перевірки або вичитки. |
| Review | Документ/код можна відкрити та перевірити за критеріями приймання або валідатором. | Перевірка пройдена успішно, зауважень немає. |
| Done | Робота повністю прийнята, закомічена в репозиторій і не потребує змін. | Ніколи (кінцева точка потоку). |

Відповідь на питання (якби таких термінових карток було 3 на тиждень):
Якби термінові картки з'являлися 3 рази на тиждень, плановий потік розробки був би повністю заблокований, а заплановані фічі беклогу прострочили б усі дедлайни (Cycle Time планових задач виріс би в рази). 
Для вирішення цієї проблеми я б застосував поєднання двох підходів:
1. **Суворий ліміт на Expedite:** встановити правило "не більше 1 Expedite-картки на тиждень".
2. **Заміна обсягу (Scope Swap):** відмовлятися брати нові Expedite-задачі без обговорення та вилучення відповідного обсягу планових задач зі спринту, або виділити окрему смугу (Swimlane) з WIP-лімітом = 1, де термінові задачи витісняють планову роботу за чіткою домовленістю із замовником.
